## Feature: auto-onboarding on first GitHub sign-in
Flow: sign in with GitHub -> if the account has never been registered -> start backend LLM pipeline
(rough profile + questions) -> land on /assessment -> standby for answers -> final enhanced profile.
- NEW `app/api/onboarding/auto/route.ts` (POST, idempotent):
  - "New" == no `candidate_profiles` row AND no `sessions` row for user_id.
  - Fail-CLOSED: if that lookup errors, return 500 rather than guessing "new" (a wrong guess would
    spawn duplicate extractions + LLM runs).
  - Requires a GitHub identity (`buildIdentity` missing list) -> else 400 `not_eligible`.
  - Creating the session is what starts the pipeline (backend returns 202, works in background).
- `components/AppShell.tsx`: fires once per mount after auth resolves; if response is `new` AND the
  user is on `home`, `setTab('assessment')`. Doesn't yank users off other tabs.
- `components/views/AssessmentContent.tsx`: adopts an in-flight session (resumable == new/pending/awaiting)
  and polls it, so refresh/reopen resumes. Completed sessions are skipped so the saved-profile view wins.
- Intake form stays inline + non-blocking during `pending` (existing render at ~line 344).

## Backend bug fixed: LLM returns `evidence` as a dict
- Symptom: sessions went `pending -> failed` with "RoughProfile ... evidence Input should be a valid
  list, input_value={'total_estimated_loc': ...}". The local OpenAI-compatible proxy
  (`OPENAI_BASE_URL=http://127.0.0.1:20128/api/v1`, model `antigravity/gemini-3.7-flash-high`, run via
  **Docker**) returns `evidence` as a stats dict, not a list.
- Fix: `_as_str_list()` helper + `field_validator("evidence", mode="before")` on `RoughProfile` and
  `SkillTag` in `backend/rag/models.py`. Matches the codebase's own stated philosophy (rubric scores
  kept as floats: "rejecting those fails the whole grade over a type that carries no meaning").
- Added `backend/tests/test_models.py` (6 tests). **55/55 pass.**

## IMPORTANT: LLM is a local Docker proxy — sessions hang if Docker is down
- `OPENAI_BASE_URL=http://127.0.0.1:20128/api/v1`. If the container is stopped, every LLM call times
  out after 60s and `api.py::_advance_safely` swallows the exception, so the session sits at `pending`
  FOREVER with no error surfaced. Symptom "session stuck on pending" == check Docker first.
- Verified full happy path once Docker was up: POST /sessions -> pending -> awaiting (rough profile +
  4 generated questions tailored to the profile) -> POST /answers -> **complete** with grade, verdict,
  tags (['CSS','HTML','frontend']) and skills. Test rows (auto-probe-*) were deleted afterwards.

## CodeMates: private lobbies (feature in progress)
- Decisions: private == **unlisted + join by exact code**; storage **Postgres + Realtime**;
  scope **core multiplayer** (create/join/leave, shared editor, cursors, chat, roster); **sign-in required**.
- The tables ALREADY EXIST in Supabase (created outside repo migrations), with exactly the columns the
  UI expects: `profiles(id,display_name,role,created_at)`, `rooms(id,code,host_id,title,status,created_at)`,
  `room_members(room_id,user_id,joined_at)`, `messages(id,room_id,user_id,body,created_at)`.
- **RLS on `rooms` was wide open** — verified: the demo user could read all 3 rooms incl. other users'
  codes (ROOM-FIFG, CM-UG7A). So lobbies were never private. Hardening requires DDL.
- **I cannot run DDL here**: no psql, no supabase CLI, no DATABASE_URL/DB password in .env. User must
  paste SQL into the Supabase SQL editor. (This is a standing environment limitation.)
- Wrote `backend/migrations/003_codemates_private_rooms.sql` (idempotent):
  drops ALL pre-existing policies on rooms/room_members/messages/profiles via a dynamic DO loop
  (named drops would leave old permissive policies behind), then adds host-or-member scoped policies,
  unique index on rooms.code, `is_room_member()` helper, and security-definer RPCs
  `create_room` / `join_room_by_code` / `leave_room`, plus a `handle_new_user` trigger that auto-creates
  a profile row on signup (with backfill) so display names and the messages->profiles join resolve.
- **Join-by-code MUST go through the RPC**: once RLS scopes rooms to host/member, a client SELECT by
  code cannot see a room it is not a member of.
- Frontend changes in `components/views/CodeMatesContent.tsx`: removed the 3 hardcoded demo rooms and
  the phantom "Custom Live Room" fallback; `loadRooms` now scopes to host-or-member via PostgREST
  `.or()`; create uses `create_room` RPC with duplicate-code retry (23505); join uses `join_room_by_code`
  with a real "No lobby found" error; both require sign-in; added `handleLeaveRoom` -> `leave_room` RPC
  (distinct from "Back to Rooms List", which keeps membership).
- `tsconfig.json` now excludes `backend/data` — the github-detector clone cache was being type-checked
  and produced hundreds of errors from unrelated cloned repos (react-router-dom, framer-motion, ...).
  tsc is clean (exit 0) after this. NOTE: `next build` hides TS errors anyway (ignoreBuildErrors: true),
  so always verify with `node node_modules/typescript/bin/tsc --noEmit --incremental false`.
- STATUS: frontend done + typechecks, but **NOT functional until the SQL is applied** (RPCs don't
